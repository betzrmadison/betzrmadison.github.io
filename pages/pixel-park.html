Pixel Park

An AI-powered predictive maintenance dashboard & hardware link for Minecraft ride control systems.

Tech Stack

Java, OpenJDK 25, Spigot/Paper API, Minecraft Protocol & Packets, Git, IntelliJ IDEA

Link to GitHub Repository

https://github.com/betzrmadison/Pixel-Park

Overview

Pixel Park is a custom Java plugin (PixelParkCore) built on OpenJDK 25 that acts as an IoT-style telemetry bridge for Minecraft theme park ride systems. By intercepting minecart movement vectors, coordinates, and rotation in real time, it converts in-game physics into live telemetry streams designed for downstream data pipelines, 3D visualization, and AI-driven anomaly detection.

Currently Implemented

  • Plugin Architecture & Core Setup: Built PixelParkCore, a modular Java server plugin compiled against OpenJDK 25, structured for low-overhead hook points on local and remote server environments.
  • Coordinate & Motion Telemetry Streaming: Intercepted entity location updates to stream minecart coordinates (X, Y, Z), velocity vectors, and pitch/yaw rotation in real time directly to the server console and structured output streams.
  • Local Test Environment: Deployed and configured a dedicated local Minecraft testing instance to validate telemetry output latency, entity tracking accuracy, and multi-cart concurrent performance.
  • Environment Configuration & Control: Configured automated build artifacts, explicit .gitignore rules for build isolation, and license management across the codebase.

Future Development

  • Arduino Hardware & Physical Controls Integration: Interfacing the plugin with an external Arduino microcontroller to sync in-game track telemetry with physical hardware indicators (such as emergency stop buttons, physical track status LEDs, and real-time control panels).
  • Packet-Level Tracking (NMS / ProtocolLib): Moving beyond default Bukkit event listeners to intercept low-level server-to-client packets directly, capturing high-frequency position ticks without adding load to the main server thread.
  • Kafka / MQTT Data Pipeline: Offloading raw telemetry streams from the console to a lightweight message broker (such as MQTT or Apache Kafka) to manage high-throughput data pipelines across software and hardware endpoints.
  • AI Anomaly & Failure Prediction Engine: Building an external analytics service that processes live velocity, location, and hardware input feeds to predict attraction track anomalies or mechanical delays before they occur.
  • 3D Real-Time Dashboard Visualization: Creating a web interface (React/Three.js or Grafana dashboard) that ingests the live telemetry stream to render an interactive 3D map of active train positions alongside physical hardware status indicators.
